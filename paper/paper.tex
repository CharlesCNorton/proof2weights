\author{Charles C. Norton}

\begin{abstract}
We define the forward passes of GPT-2, SmolLM2-135M-Instruct and Qwen3.5-0.8B,
whose gated DeltaNet layers carry a state matrix through the sequence, in the
Rocq prover with all arithmetic in IEEE-754 binary32 through Flocq, and extract
them to OCaml programs that run the published checkpoints. On 300 windows of
held-out text per model, 4{,}800 next-token distributions each, the extracted
forward pass and PyTorch in float32 choose the same top-1 token at every
position, with every logit within $1.6\times10^{-3}$, and the same holds at
whole blocks of 64 tokens, at GPT-2's full 1024 positions and at 2048 tokens on
SmolLM2. A second extraction that
trusts no floating-point hardware computes, at every operation and for every
input, the binary32 value the hardware extraction computes; that equality is
proved at the level of floats, so overflow, infinities, NaNs and signed zeros
are inside it, and the two assumptions the hardware extraction makes about its
host are decided on that host by a self-test. We further prove that cached
autoregressive decoding computes exactly the binary32 values
full recomputation computes, and that the three forward passes are causal. Used
as a fixed reference, the extracted pass attributes llama.cpp's divergence, top-1
changes at up to 7 of 4{,}800 positions and logit shifts up to $1.7$, to four
implementation choices; with all four removed, llama.cpp agrees as closely as
PyTorch.
\end{abstract}

\section{Introduction}

A neural network deployed in float32 has no canonical output. Implementations
disagree across BLAS backends, across fused multiply-add contraction decisions
and across GPU reduction orders, and the disagreement is large enough to change
decoded tokens \cite{tinker2025,gensyn2025}. There is consequently no artifact
one can point to as the answer a given checkpoint and prompt determine.

The usual formal treatment of a network establishes a property in a proof
assistant and implements the deployed system separately, so the deployed
numbers transcribe the proven ones and the deployed arithmetic is a separate
implementation of the proven arithmetic. This work takes the other route: the
weights are read, the arithmetic is performed and the logits are produced by
functions defined in Rocq and extracted verbatim, so the arithmetic executed at
inference time is the arithmetic the proofs concern.

The contributions are the following.
\begin{itemize}
\item A binary32 definition of three architectures, including a gated DeltaNet
  recurrence, extracted to programs that run the published GPT-2,
  SmolLM2-135M-Instruct and Qwen3.5-0.8B checkpoints
  (Section~\ref{sec:exec}), measured against PyTorch and llama.cpp on 300
  held-out windows of 16 tokens per model, on sixty whole blocks of 64, and at
  window lengths to 2048 (Section~\ref{sec:agree}). For each
  model a runner whose forward pass is the extracted definition rather than a
  loop rebuilt around it reproduces the same checkpoint's PyTorch oracle.
\item Two extraction modes from one source, with a proof at the level of floats
  that they compute the same binary32 value at every operation for every input,
  overflow, infinities, NaNs and signed zeros included, and a self-test that
  decides on the host the two assumptions the hardware mode makes about it
  (Section~\ref{sec:tcb}).
\item Proofs that cached decoding equals full recomputation, as equalities of
  binary32 values, and that the three forward passes are causal
  (Section~\ref{sec:cache}).
\item A composed rounding-error bound from the primitives to the logits of all
  three architectures, a GPT-2 forward pass that computes a bound on each
  logit's distance from exact real arithmetic while it runs, and a
  backward-error statement for the linear layers whose only hypothesis is that
  nothing overflows (Section~\ref{sec:err}).
\item Bounds from every elementary function the models evaluate to the
  mathematical function (Section~\ref{sec:elem}), and the error of each
  measured at every one of the $2^{32}$ binary32 inputs
  (Section~\ref{sec:exh}).
\item A differential oracle for float32 implementations, which separates
  PyTorch's residual into reduction order and elementary functions
  (Section~\ref{sec:agree}) and attributes llama.cpp's divergence to four
  implementation choices (Section~\ref{sec:diff}).
\end{itemize}

The results rest on nothing beyond the four classical axioms of the Rocq
real-number library that Flocq inherits, except the series bounds of
Section~\ref{sec:elem}, which add CoqInterval's primitive-float, 63-bit-integer
and primitive-array interface.

\section{The development}
\label{sec:dev}

\subsection{Arithmetic}

The floating-point type is Flocq's \code{binary\_float} at precision $24$ and
exponent bound $128$. Addition, multiplication, division, square root,
negation, absolute value and comparison are Flocq's \code{Bplus}, \code{Bmult},
\code{Bdiv}, \code{Bsqrt}, \code{Bopp}, \code{Babs} and \code{Bcompare} under
round-to-nearest, ties-to-even. Every scalar the networks compute is produced
by one of these operations, and everything else is list plumbing that performs
no arithmetic. A weight is decoded from its four little-endian bytes through
Flocq's \code{b32\_of\_bits} composed with the single-NaN collapse, so a loaded
value is the IEEE-754 value its bytes denote.

\subsection{The elementary functions}

Each elementary function is a composition of the primitives, and each constant
is a quotient of integers that binary32 rounds once.

\paragraph{Exponential.} The argument is saturated to $[-88, 88]$ and written
as $x = k\log 2 + r$, with $k$ the nearest integer to $x/\log 2$. The reduction
subtracts $k\cdot\frac{355}{512}$ and adds $k\cdot\frac{14581891}{2^{36}}$; the
first constant has nine significant bits, so its product with every $k$ in
$[-127, 127]$ is exact, and the two together lie within $2\times10^{-12}$ of
$\log 2$. A Taylor polynomial of degree seven evaluates $e^r$ for
$|r|\le 0.35$, and the result is multiplied by $2^k$, assembled from exact
powers of two.

\paragraph{Rounding to an integer.} \code{f32\_round\_int} adds and subtracts
$c = 1.5\cdot2^{23}$. For $|y| < 2^{22}$ the sum lies in $[2^{23}, 2^{24})$,
where the unit in the last place is one, so the result is the nearest integer
for arguments of either sign.

\paragraph{Sine and cosine.} The argument is reduced by $k$ times a split of
$2\pi$, $\frac{201}{32} + \frac{8312081}{2^{32}}$, with $k$ the nearest integer
to $x/2\pi$, and Taylor polynomials through degree $19$ and $18$ are evaluated
on the result. The polynomial divides by the factorials as binary32 stores
them, which from $14!$ upward are not the factorials, and the bounds of
Section~\ref{sec:elem} are stated on the stored values.

\paragraph{Logarithm and the rest.} Qwen3.5's decay term needs a logarithm,
always of an argument in $(1, 2]$, where
$\log m = 2\operatorname{artanh}\frac{m-1}{m+1}$ converges in seven terms with no
reduction. Sigmoid is $1/(1+e^{-x})$ and $\tanh x = 2\sigma(2x) - 1$. GELU is the
form GPT-2 is trained with,
$\frac{x}{2}\bigl(1 + \tanh(\sqrt{2/\pi}\,(x + 0.044715\,x^3))\bigr)$, SiLU is
$x\,\sigma(x)$, softplus is $\max(x,0) + \log(1 + e^{-|x|})$, which confines the
logarithm to $(1, 2]$, and softmax subtracts the row maximum before
exponentiating.

\subsection{Architectures}

The GPT-2 path is a pre-norm decoder stack: layer normalization, a fused
query/key/value projection, multi-head causal attention, a residual, layer
normalization, a GELU feed-forward, a residual, a final layer normalization and
a tied-embedding logit projection. Causal attention computes row $i$ by
attending the $i$-th query over the first $i + 1$ keys and values with a
max-shifted softmax, so later positions contribute no arithmetic to earlier
rows.

The Llama path replaces layer normalization with RMSNorm, learned position
embeddings with rotary embeddings, multi-head with grouped-query attention, and
the GELU feed-forward with SwiGLU.

The Qwen3.5 path alternates three gated DeltaNet layers \cite{gateddeltanet}
with one gated full-attention layer. A DeltaNet layer projects its input to a
fused query/key/value triple, applies a depthwise causal convolution,
$\ell_2$-normalizes query and key, and runs a recurrence over a per-head state
matrix $S \in \mathbb{R}^{d_k \times d_v}$:
\[
  S_t = e^{g_t}\,S_{t-1}
        + k_t\big(v_t - S_{t-1}^{\top}k_t\big)^{\!\top}\!\beta_t,
  \qquad
  o_t = S_t^{\top} q_t ,
\]
with $g_t = -e^{A_{\log}}\operatorname{softplus}(a_t + b_{\mathrm{dt}})$ and
$\beta_t = \sigma(b_t)$. Each read-out is normalized against a gate by a
SiLU-gated RMSNorm. The full-attention layers normalize the per-head query and
key with a zero-centred RMSNorm, rotate a quarter of each head, and gate their
output elementwise by $\sigma$ of a stream carried in the query projection. For
text-only input the multimodal rotary embedding coincides with ordinary rotation
on that quarter.

\section{Extraction and the trusted computing base}
\label{sec:tcb}

The inductive extraction keeps \code{binary32} as Flocq's inductive
\code{binary\_float} and $\mathbb{Z}$ and \code{positive} as inductive
datatypes, so every float operation is the computational content of its
definition. $\mathbb{Z}$ is not mapped to machine integers, since a
mantissa-alignment shift or an intermediate product can leave their range. Only
\code{nat}, which carries indices, dimensions and token identifiers, extracts
to \code{int}. This mode trusts no floating-point hardware.

The native extraction maps \code{binary32} to the host's hardware float, in the
manner CompCert extracts its verified floats \cite{compcertfp}. Each operation
is the binary64 result rounded to binary32 through an \code{Int32} bit
round-trip. Write $\mathrm{widen}$ for the exact embedding of a binary32 into
binary64 that occurs when an OCaml \code{float} holding a binary32 value enters
an arithmetic operation, and $\mathrm{narrow}$ for the round-to-nearest-even
conversion back that the round-trip performs, with overflow to an infinity of
the operand's sign.

\begin{theorem}[\code{narrow\_widen\_plus}, \code{\_minus}, \code{\_mult}, \code{\_div}, \code{\_sqrt}]
\label{thm:narrow}
For all binary32 values $x$ and $y$,
\[
  \mathrm{narrow}\bigl(\mathrm{widen}(x) \mathbin{\circ_{64}} \mathrm{widen}(y)\bigr)
  = x \mathbin{\circ_{32}} y
\]
for $\circ \in \{+, \times, \div\}$, with subtraction the case
$\mathrm{narrow}(\mathrm{widen}(x) +_{64} -\mathrm{widen}(y))$ because
\code{f32\_minus} is addition after negation and the native build extracts it
that way, and likewise
$\mathrm{narrow}(\sqrt{\vphantom{x}}_{64}\,\mathrm{widen}(x)) = \sqrt{\vphantom{x}}_{32}\,x$.
There is no side condition: the statement quantifies over the constructors of
\code{binary\_float}, so infinities, NaNs, signed zeros, underflow and overflow
are all inside it.
\end{theorem}

The proof is one bridge lemma applied five times. For operands on which the
operation's Flocq correctness theorem applies, the binary64 result is the
correct rounding of the same exact real value the binary32 result rounds; the
binary64 rounding never overflows, because a binary32 pair produces a quotient
of magnitude at most $2^{277}$; narrowing that result is correct rounding
again, and double rounding is harmless, by Flocq's double-rounding development
\cite{roux2014} instantiated at the two formats, so the two sides
have the same value, the same finiteness and the same sign, which determines a
float. The remaining operand shapes are decided by computation on the
constructors. \code{narrow\_widen} states the special case that narrowing a
widened binary32 returns it.

The consequence is that the two extraction modes compute the same binary32
value at every operation for every input, so a number measured on the native
build is a number of the inductive build. What the native build still assumes
is that the host's binary64 arithmetic is IEEE-754 round-to-nearest-even with
no excess precision and no contraction of a multiply and an add, and that
\code{Int32.bits\_of\_float} rounds to nearest. A self-test shipped with the
runners decides both on the host that runs it. The elementary functions extract
structurally in both modes as the same compositions of the primitives.
Table~\ref{tab:tcb} states the two trusted bases.

\section{Execution on published checkpoints}
\label{sec:exec}

Each model has two runners. The first does not write the forward pass. It hands
the extracted loader a fetch of one byte of the file's data section, and
\code{f32\_load\_model\_pre}, \code{f32\_load\_llama} or
\code{f32\_load\_qwen} looks up each tensor's offset in the header, decodes it
and assembles the weight record, after which the extracted pass runs on that
record. What this runner does natively is read the file and answer the fetch.
The development's first loader takes the data section as a list of bytes; this
one takes the fetch, and runs on a file of any size.

\begin{theorem}[\code{f32\_load\_model\_pre\_correct}]
On a header whose tensors carry two offsets bounding the expected number of
values, the record the reader-based loader assembles is the record
\code{f32\_load\_model} defines, transposed.
\end{theorem}

\code{f32\_load\_llama\_correct} and \code{f32\_load\_qwen\_correct} say the
same of the other two records, each field against the named load of its tensor.
The transposition is GPT-2's. Its linear layer transposes its weight, and the
extracted transpose indexes a list of lists, which is quadratic in the output
dimension, so the loader reads each matrix in transposed order
(\code{decode\_transposed\_correct}) and the pass that runs is the same pass
over weights stored that way, proved to return on the transpose of a model what
\code{f32\_gpt2\_logits} returns on the model
(\code{f32\_gpt2\_logits\_pre\_correct}). The Llama and Qwen3.5 definitions
take the weights in the order the file holds them, and their rotary tables are
built inside the extraction.

The second runner caches, where the first recomputes the sequence at every
step. It writes the layer loop in OCaml around the extracted operators and
streams weights layer by layer, so its arithmetic is
verified and its composition is not; the equalities of
Section~\ref{sec:cache} are what cover its caches. It is the one that decodes
autoregressively, and the one the measurements of Section~\ref{sec:agree} were
taken on. The two runners agree: each verified runner reproduces its
checkpoint's stored PyTorch ranking, and on GPT-2 and SmolLM2 its ten highest
logits are the cached runner's to every digit printed.

Table~\ref{tab:models} gives the three checkpoints and what a forward pass
costs in each mode. Against PyTorch in float32 on a stored prompt, the largest
logit difference among the top candidates is $7.3\times10^{-5}$ absolute and
$1.5\times10^{-6}$ relative, and the greedy continuations of SmolLM2 and
Qwen3.5 are token-identical over twelve tokens. Timings are single-threaded
wall clock on an Intel i9-12900H.

\section{Agreement on held-out text}
\label{sec:agree}

The development is the specification of what these models compute in binary32,
and its agreement with other implementations is a measurement. For each
model, the WikiText-2 raw test split \cite{wikitext}, tokenized by the
model's own tokenizer, was cut into consecutive blocks of 64 tokens, and the
first 16 tokens of 300 blocks spread evenly over the split form the windows.
Each window was run through the native extraction, through PyTorch in float32
on an Intel i9-13900KF and on an RTX 6000 Ada GPU, and through llama.cpp
\cite{llamacpp} on the same CPU and GPU from a float32 GGUF conversion. The
conversion preserves the weights: on SmolLM2 every tensor of the GGUF holds the
values of the \code{safetensors} the extracted pass loads, the query and key
projections up to the row permutation the converter applies for its rotary
convention, so the deviations reported below are differences in arithmetic.
Each implementation returns the logits of all 16 positions, 4{,}800 next-token
distributions per model. PyTorch runs with eager attention and with TF32
disabled, and Qwen3.5's gated DeltaNet runs its PyTorch fallback, a chunked form
of the delta rule. llama.cpp runs with flash attention disabled and otherwise
in its default configuration.

\subsection{Longer windows, other implementations, and the precision deployments use}
\label{sec:longer}

Sixteen tokens is short, and a window's later positions attend over more keys
and carry larger rotary angles. The evaluation is repeated on whole blocks of
$64$ tokens for all three models (Table~\ref{tab:long}), and on long windows:
GPT-2 over the whole of its position table at $1024$, and SmolLM2 at $2048$
(Table~\ref{tab:longctx}). Both tables carry llama.cpp beside PyTorch
and bfloat16 beside float32, bfloat16 being the precision deployments use.
Qwen3.5 has a further row: the gated delta rule through
flash-linear-attention's fused Triton kernels, which is the path a deployment
of that architecture takes, in float32 with the depthwise convolution left on
the torch path.

Top-1 agreement with PyTorch in float32 is unaffected by any of it. At $64$
tokens PyTorch returns the extracted top-1 token at all $3{,}840$ positions of
each of the three models, at $1024$ at all $3{,}072$ of GPT-2's, and at $2048$
at all $6{,}144$ of SmolLM2's. The top ten agree in order at every position of
SmolLM2 and Qwen3.5 at every length; on GPT-2 between one and four positions
reorder, of $3{,}840$ at $64$ tokens and $3{,}072$ at $1024$. Perplexity moves
by less than one part in $10^{6}$ in float32 at every length.

The largest logit difference does not follow the length monotonically. On GPT-2
it is six times larger at $1024$ than at $64$, $9.89\times10^{-3}$ against
$1.68\times10^{-3}$; on SmolLM2 it is five times smaller at $2048$ than at
$64$, $2.15\times10^{-4}$ against $1.17\times10^{-3}$.

llama.cpp in float32 changes the top-1 token at $1$ to $14$ positions per model,
device and length, which Section~\ref{sec:diff} attributes. bfloat16 is a
different regime, and the two ways of reaching it separate. On the two models
measured both ways at $64$ tokens, reading bfloat16 weights and computing in
float32, as llama.cpp does, changes $26$ and $210$ top-1 tokens; computing in
bfloat16 as well, as PyTorch does, changes $149$ and $468$, between two and six
times as many, and moves a logit by $12.5$ against $7.4$. Length widens that gap sharply: at GPT-2's $1024$ positions
PyTorch in bfloat16 moves a logit by $298$ and leaves the top ten in order at
$113$ positions of $3{,}072$. The fused float32 kernels sit between the two,
changing six top-1 tokens where the unfused float32 path changes none.

\subsection{What the residual against PyTorch is}

The residual PyTorch leaves has two possible sources: it evaluates the
elementary functions with its own implementations rather than the series of
Section~\ref{sec:elem}, and it accumulates its matrix products in a different
order. The two are separated on GPT-2 by running the forward pass in numpy
float32 twice over the same checkpoint and the same windows, once with numpy's
exp and GELU and once with the extracted ones, against the extracted reference. Over twenty windows of 64 tokens the maximum
absolute difference moves from $1.766\times10^{-3}$ to $1.678\times10^{-3}$ and
the mean from $6.159\times10^{-5}$ to $6.112\times10^{-5}$; PyTorch sits at
$1.678\times10^{-3}$ and $6.199\times10^{-5}$. Substituting the elementary
functions therefore accounts for five percent of the maximum and under one
percent of the mean, and what is left, which is nearly all of it, is reduction
order. Random small models show the same signature: against a numpy float32
implementation the mean logit error rises by a factor of $12.5$ from width $8$
to width $64$ at four layers and by $1.4$ from one layer to eight, which is
what accumulating longer dot products in a different order predicts
\cite{highammary2019}.

\section{Cached decoding and causality}
\label{sec:cache}

Autoregressive generation performs a prefill over the prompt and then one
decode step per token, reusing state the earlier steps produced, while the
definitions recompute the whole sequence. The two perform the same
multiplications in different groupings, and binary32 addition is not
associative, so agreement is not automatic. Qasim et al.\ \cite{residualstream}
show that keys and values are deterministic projections of the residual stream
and verify bit-identical recomputation of them across six models from four
architecture families. The equality proved here is between a decode step that
reuses cached state and a full recomputation of the sequence, stated as an
equality of binary32 values.

\subsection{The recurrent half}

\code{f32\_delta\_scan} returns the per-token outputs of the gated delta rule,
and \code{f32\_delta\_state} is the same recursion returning the state.

\begin{theorem}[\code{delta\_scan\_app}]
For sequences split anywhere, with the five per-token streams of equal length on
the first part,
\[
  \mathrm{scan}(\beta_1\beta_2, g_1g_2, q_1q_2, k_1k_2, v_1v_2)(S)
  = \mathrm{scan}(\beta_1,\dots)(S)
    \mathbin{+\!\!+} \mathrm{scan}(\beta_2,\dots)\big(\mathrm{state}(\beta_1,\dots)(S)\big).
\]
\end{theorem}

Its corollary \code{delta\_scan\_snoc} is the decode step: extending the
sequence by one token appends exactly the output of one step from the threaded
state. \code{conv\_window\_cached\_correct} shows that
appending the current input to the trailing $k-1$ inputs forms exactly the
window \code{f32\_causal\_conv1d} reads, and \code{conv\_hist\_step} that the
runner's update maintains that invariant.

\subsection{The attention half}

\begin{theorem}[\code{causal\_attention\_app}, \code{causal\_attention\_snoc}]
If $k_1$ and $v_1$ have as many rows as $q_1$, causal attention over
$q_1q_2$, $k_1k_2$, $v_1v_2$ is causal attention over $q_1, k_1, v_1$ followed
by the rows of $q_2$, each attending over the corresponding prefix of the
extended keys and values. In particular one more position appends exactly the
new query attending over every cached key and value.
\end{theorem}

\subsection{The decode step}

\begin{definition}
A function $F$ from sequences to sequences is \emph{causal} when
$|F(x)| = |x|$ and $\mathrm{firstn}\,|x|\,(F(x \mathbin{+\!\!+} y)) = F(x)$ for
all $x, y$.
\end{definition}

The three forward passes are causal (\code{causal\_gpt2\_forward},
\code{causal\_llama\_forward}, \code{causal\_qwen\_forward}), the Llama and
Qwen3.5 ones whenever the key/value heads divide the query heads. A decoder
never evaluates the sequence function on the whole sequence. It takes one step
per token and emits the last row of each. Write that decoder over an arbitrary
sequence function as
\[
  \mathrm{decode}(F)(x) =
  \bigl[\,\mathrm{last}\,F(\mathrm{firstn}\,(i{+}1)\,x)\,\bigr]_{i < |x|}.
\]

\begin{theorem}[\code{decode\_stream\_correct}]
For every causal $F$ and every $x$, $\mathrm{decode}(F)(x) = F(x)$.
\end{theorem}

The proof applies causality at each prefix, and the theorem is instantiated at
the three models. Within a step, the cache theorems above compute the row from
the state the earlier steps left.

\section{Rounding error}
\label{sec:err}

\subsection{The rounding model}

Write $u = 2^{-24}$ for the unit roundoff of binary32 and
$\eta = 2^{-150}$ for half its smallest positive value.

\begin{theorem}[\code{f32\_round\_mixed}]
For every real $z$ there are $d, e$ with $|d| \le u$, $|e| \le \eta$ and
$de = 0$ such that the binary32 rounding of $z$ equals $z(1+d) + e$.
\end{theorem}

This is Flocq's \code{error\_N\_FLT} at binary32. Rounding is relative in the
normal range and absolute near zero, and the statement needs no hypothesis on
$z$, so it holds at the exact zeros a network produces structurally: the
DeltaNet state starts at zero, the convolution pads with zeros, and any zero
weight zeroes a product.

\subsection{Propagation}

The relation $\mathrm{ok}\;\delta\;x\;r$ says that the float $x$ is finite and
$|x - r| \le \delta$, where $r$ is the value exact real arithmetic produces from
the same inputs. The side condition $\mathrm{regz}\;M\;z$ is
$|z|(1+u) + \eta \le M$, an overflow budget with no lower bound. An
amplification budget $L$ satisfies $L \ge 2$, $L \ge 2M$,
$L \ge 1/m + M/m^2$ and $L \ge 1/(2\sqrt{m})$, where $m$ bounds denominators and
radicands from below.

\begin{lemma}[\code{ok\_plus}, \code{ok\_mult}, \code{ok\_div}, \code{ok\_sqrt}]
If the operands are $\mathrm{ok}\;\delta$, the exact result of the operation on
the floats satisfies $\mathrm{regz}\;M$, the magnitudes the operation multiplies
are at most $M$ and the denominators and radicands at least $m$, then the
result is $\mathrm{ok}\,(uM + \eta + L\delta)$.
\end{lemma}

A stage of arithmetic depth $k$ iterates this affine map $k$ times, giving the
error $\mathrm{err}_k$, and because $\mathrm{err}_k$ is monotone in $k$ a stage
may be charged more depth than it uses. Structural lemmas transport the
relation through the list plumbing unchanged. Chaining the primitive lemmas
through the dot product, linear layers, layer normalization, the exponential,
softmax, causal attention with head splitting and concatenation, the block and
the stack gives the bound at the GPT-2 logits (\code{ok\_gpt2\_logits\_full}).
The same chain runs through RMSNorm, rotary embedding and SwiGLU to the Llama
logits (\code{ok\_llama\_logits\_full}), and through the logarithm, softplus,
the two further RMSNorm variants, the convolution, the gated delta step and
scan, and both Qwen3.5 mixers to the Qwen3.5 logits
(\code{ok\_qwen\_logits\_full}).

The side conditions of each stage are collected in a record: one overflow
condition per operation, bounds on the magnitudes it multiplies, and, for the
exponential, the hypothesis that the float reduction selects the integer $k$
the real evaluation selects. They are hypotheses about intermediate values; the
records of the exponential, sigmoid, tanh and GELU are discharged by
computation at an exact zero, and the exponential's at $-1000$, which saturates
to $-88$ and whose result is subnormal, as a masked attention score is.

\subsection{A forward pass that carries its bound}
\label{sec:runerr}

The records above are hypotheses about intermediate values, and a checkpoint
produces billions of them. The annotated forward pass moves the side conditions
into the computation. The GPT-2 forward pass is written once over an abstract
arithmetic, a record of nine operations (constants, addition, negation,
multiplication, division, square root, maximum, the exponential and the dot
product), and instantiated three times. At binary32 it is
\code{f32\_gpt2\_logits}, by conversion. At exact real arithmetic, with the
exponential taken on its argument saturated to $[-88, 88]$, it is the
reference. At the annotated arithmetic, every value is a binary32 result paired
with a binary64 bound.

\begin{definition}
An annotated value $(x, \delta)$ is within its bound of a real $r$, written
$\mathrm{aok}\,(x,\delta)\,r$, when finiteness of $\delta$ implies that $x$ is
finite and $|x - r| \le \delta$.
\end{definition}

Each annotated operation computes its binary32 result exactly as the extracted
primitive does. It computes the bound in binary64 with outward rounding: every
intermediate is rounded to nearest and moved to its floating-point successor or
predecessor, so a finite bound lies above the real quantity it bounds. The
rounding error of the operation is read off its result as
$(u|w| + \eta)(1 + 2u)$, a consequence of \code{f32\_round\_mixed}. A condition
the analysis needs, such as a divisor that stays away from zero after its own
bound is subtracted, is tested on the values the pass computes, and a failed
test returns an infinite bound, which asserts nothing. Every annotated operation
therefore preserves $\mathrm{aok}$ with no hypothesis. The exponential is
treated the same way: whatever integer $n$ the float reduction selects,
$e^{x} = 2^{n} e^{x - n\log 2}$, so its test is on the reduced argument and not
on agreement with the real reduction.

\begin{theorem}[\code{gpt2\_logits\_bounded}]
For every configuration, model and token sequence, the binary32 components of
the annotated forward pass are the logits \code{f32\_gpt2\_logits} returns, and
each is $\mathrm{aok}$ of the corresponding logit of the reference network on
the same weights and tokens.
\end{theorem}

The bound is computed by the pass from the values that pass produces, so it
holds for the input the pass was run on.

The growth is the sensitivity of the layers themselves. A linear layer carries
an input error bounded componentwise by $\varepsilon$ to an output error
bounded by $\max_i \sum_j |W_{ij}|\,\varepsilon$, and the error vector whose
signs match row $i$ attains it, so a bound that holds for every input pays that
factor. On GPT-2 small those row sums lie between $117$ and $1120$ per matrix,

stays well inside that, carrying a separate bound per component rather than
one $\varepsilon$ for the vector. What separates its $1.8\times10^{-5}$ at one
layer from the observed $3.4\times10^{-8}$ is that rounding errors do not align
with any row, which is the distance between a worst case and an average one. A
backward-error formulation pays the same row sums once its relative
perturbation of the weights is turned into a forward bound. The backward
theorem below is a different statement, whose perturbation is set by the length
of one dot product rather than by the depth of the network.

\subsection{Backward error}

\begin{theorem}[\code{f32\_dot\_backward\_mixed}]
If no rounding in $\mathrm{dot}(x, y)$ of length $n$ overflows, the computed
value equals $\sum_i x_i y_i t_i + \delta$ with
$|t_i - 1| \le (1+u)^{n+1} - 1$ and
$|\delta| \le 2 n \eta (1+u)^{n}$.
\end{theorem}

The perturbation is set by the length of the one dot product, not by the depth
of the network. The classical statement \cite{higham2002} is the case
$\delta = 0$, which needs every product and every partial sum to be zero or at
least $2^{-126}$ in magnitude, where rounding is relative. That fails where the
networks compute: a masked attention score is the exponential of a saturated
argument and is subnormal, and the products a dot product then accumulates are
subnormal too. The displacement $\delta$, a multiple of half the smallest
positive binary32, is what covers those rows. Overflow is the only hypothesis,
and the statement lifts unchanged to the matrix-vector product and to the
tied-embedding logit projection of all three models
(\code{logits\_backward\_mixed}), where a row of length at most $k$ carries at
most $2 k \eta (1+u)^{k}$.

\section{The elementary functions against mathematics}
\label{sec:elem}

The propagation relation compares a float evaluation with the real evaluation
of the same expression. This section bounds the distance from the real
evaluation to the mathematical function, and the composition by the triangle
inequality gives the distance from the extracted function to the mathematical
one.

\subsection{Series}

CoqInterval \cite{coqinterval} proves the truncation error of each polynomial
with the divisors the code holds: the sine polynomial within $2\times10^{-9}$ of
$\sin$ and the cosine polynomial within $2\times10^{-8}$ of $\cos$ on
$[-3.17, 3.17]$, the exponential polynomial within $10^{-8}$ of $\exp$ for
$|r| \le 0.35$, and the arctanh series within $2\times10^{-8}$ of $\log$ on
$[1, 2.0001]$, together with bounds on the stored constants.

\subsection{Exponential}

\begin{theorem}[\code{exp\_core\_vs\_true}]
For $-88 \le x \le 88$ the real evaluation $E(x)$ of the reduced exponential
satisfies $|E(x) - e^x| \le 1.6\times10^{-8}\, e^x$.
\end{theorem}

The reduced argument satisfies $|r| \le 0.35$. The polynomial is within
$10^{-8}$ of $e^r$, the stored split of $\log 2$ moves the exponent by at most
$127 \cdot 2\times10^{-12}$, which changes the exponential by a relative
$4\times10^{-10}$, and multiplying by $2^k$ scales both errors by the same
factor as $e^x$. \code{ok\_exp\_true} composes this with the propagation bound;
the relative form is what the scaling makes possible, since no step amplifies
an incoming relative error.

\subsection{Sine and cosine}

\begin{theorem}[\code{reduce\_vs\_true}]
For $|x| \le 262144$ the real reduction $\rho(x) = x - k\,(201/32) - k\,(8312081/2^{32})$
satisfies $|\rho(x)| \le 3.16$, $|\sin\rho(x) - \sin x| \le 8.4\times10^{-7}$ and
$|\cos\rho(x) - \cos x| \le 8.4\times10^{-7}$.
\end{theorem}

The range is the largest rotary angle any of the three checkpoints forms. An
angle is a position times an inverse frequency, the largest inverse frequency
is one, so the largest angle is the context length, and Qwen3.5's $262144$ is
the longest. The integer $k$ is at most $41722$ in magnitude, the stored split
differs from $2\pi$ by at most $2\times10^{-11}$, and the stored $1/2\pi$
differs from $1/2\pi$ by at most $10^{-8}$, which keeps $x - 2\pi k$ within
$3.159$ of zero.
Periodicity over the integers and the Lipschitz bounds
$|\sin p - \sin q| \le |p - q|$ and $|\cos p - \cos q| \le |p - q|$, both derived
from the product formulas, finish the proof. \code{ok\_reduce\_2pi} carries the
propagation relation through the reduction under the same kind of hypothesis
as the exponential's, that the float and real evaluations select the same $k$.

The reduction's bound is proved under the hypothesis that the float and real
reductions select the same $k$; the exhaustive sweep of Section~\ref{sec:exh}
bounds the error at every input whether or not they do.

\begin{corollary}[\code{ok\_sin\_true\_full}, \code{ok\_cos\_true\_full}]
Under the reduction's and the polynomial's side conditions, for
$|x| \le 262144$ the extracted \code{f32\_sin} is within
$\mathrm{err}_{n+23} + 8.5\times10^{-7}$ of $\sin x$ and \code{f32\_cos} within
$\mathrm{err}_{n+22} + 8.7\times10^{-7}$ of $\cos x$, where the input is
$\mathrm{ok}\;\mathrm{err}_n$.
\end{corollary}

\subsection{The compositions}

Sigmoid follows from the exponential by the inequality
$|1/(1+a) - 1/(1+b)| \le \delta$ whenever $|a - b| \le b\delta$ and
$\delta \le 1$, which gives $|\sigma_{\mathrm{real}} - \sigma| \le 1.6\times10^{-8}$
on $[-88, 88]$. The identity $\tanh y = 2\sigma(2y) - 1$ doubles it. Softplus
uses $\max(x,0) + \log(1 + e^{-|x|}) = \log(1 + e^x)$ and
$|\log p - \log q| \le |p - q|$ for $p, q \ge 1$, derived from
$1 + t \le e^t$. GELU additionally needs $|\tanh s - \tanh t| \le |s - t|$,
which follows from $|\sigma(u) - \sigma(v)| \le \frac14|u - v|$, proved on the
whole line by the mean value theorem, together with bounds on its two stored
constants. Table~\ref{tab:elem} lists the resulting bounds beside the largest
error measured over every binary32 input of each domain
(Section~\ref{sec:exh}); the measured errors include the rounding the proved

\subsection{Every binary32 input}
\label{sec:exh}

An exhaustive sweep performs the same compositions, in the same order, with
each primitive written as the binary64 operation narrowed to binary32, which
Theorem~\ref{thm:narrow} makes the same function, and evaluates \emph{every}

Three things follow. Square root is correctly rounded at every input. The
exponential is within one unit in the last place everywhere, and the logarithm
within two. And the functions built on a difference of nearly equal quantities
lose all relative accuracy near their zeros: $\tanh$ is $2\sigma(2x) - 1$, so

million units in the last place, and as an absolute error of

and cosine lose accuracy the same way at their own zeros.

Each choice alone, with the other three removed, changes top-1 tokens on at
least one model and multiplies the largest logit deviation by about 90 to
1{,}000 on every model it applies to, the kernel and TF32 by the most.

The counts are not monotone in the number of choices removed, because the
kernel and the math mode govern the same matrix products. On GPT-2 on the GPU,
removing \code{mul\_mat\_f} while TF32 remains enabled raises the top-1
differences from 7 to 11: the products the kernel handled fall to cuBLAS, which
in TF32 math mode carries a ten-bit significand. The three paths order by
accuracy as cuBLAS in float32, then the kernel, then cuBLAS in TF32, so
removing the kernel is an improvement only once TF32 is off. The two choices
have to be read as a pair, and the row with both removed is the float32 path.
With all
four removed, llama.cpp agrees with the extracted forward pass as closely as
PyTorch does on both backends, with every logit within $1.79\times10^{-3}$; its
one top-1 difference, on SmolLM2 on the GPU, falls where the two highest
extracted logits are $3.2\times10^{-5}$ apart.

\section{Related work}

Flocq \cite{flocq} provides the IEEE-754 formalization this development computes
in; CompCert's verified floating point \cite{compcertfp} is the model for
extracting Flocq arithmetic to an executable; the double-rounding results
instantiate Roux's development \cite{roux2014}; and Coq's primitive floats
\cite{primfloats} are an alternative route to native speed with a different
trusted base. CoqInterval \cite{coqinterval} discharges the series bounds.

TorchLean \cite{torchlean} is a framework for formalizing, executing and
verifying neural networks in Lean~4, with executable IEEE-style binary32
components and a rounding model among much else. The development here has a
narrower operator set and a different object: definitions extracted and
executed on published checkpoints, with results about that execution. George
\cite{torchleancheck} reports a Lean layer over TorchLean that checks exported
checkpoint files and traces against the claim they support. Earlier
proof-assistant treatments of neural networks work at smaller scale: Certigrad
\cite{certigrad} verifies a stochastic computation graph over the reals, MLCert
\cite{mlcert} extracts quantized networks, and Brucker and Stell \cite{brucker}
handle feedforward classifiers in Isabelle/HOL. Jia and Rinard \cite{jiarinard}
show that floating-point error in network verifiers is exploitable.

For mechanized error analysis the closest work is LAProof \cite{laproof}, which
proves forward and mixed backward bounds for dot products and matrix-vector
products with underflow handled; the rounding model of Section~\ref{sec:err} is
the same device. VCFloat \cite{vcfloat} treats approximation as well as
rounding error. For transformers, Budzinskiy et al.\ \cite{budzinskiy} give a
mixed-precision stability analysis covering normalization layers, softmax and
self-attention.

Batch-invariant kernels \cite{tinker2025} and RepOps \cite{gensyn2025} address
nondeterminism by fixing the reduction order in the implementation rather than
specifying it in a proof assistant, and Cankaya \cite{bitexact} shows that
bit-exact recomputation is possible across NVIDIA GPU variants by software
emulation; the reference there is a rerun of the same software, where the
reference here is a definition. Correctly rounded binary32 elementary
functions \cite{rlibm32,coremath} are an alternative to the series used here,
which would make the reference canonical against mathematics at the cost of
moving it away from PyTorch, whose backends are not correctly rounded.
